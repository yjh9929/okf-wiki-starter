지금 하는 작업

1 · 정리 (Ingest)

참고

관심있는 주제가 없으면 예시 주제들 중에 선택할 수 있게 합니다.
준비

실습 주제를 고릅니다

한 주제에 대해 서로 다른 글 두세 개면 충분합니다. 겹치는 내용이 있어야 합쳐지는 과정을 볼 수 있습니다.

수업

  • 지난 학기 교과목 수업 자료
  • 관련해서 내가 한 과제 모음
  • 시험 대비로 흩어져 있는 필기

전공 · 연구

  • 관심 있는 연구 분야의 논문
  • 학회나 연구실에서 나온 자료
  • 트랜스포머와 어텐션

진로 · 취업

  • 가고 싶은 회사의 기술 블로그
  • 직무별 인턴 후기 모음
  • 대학원 진학 준비 과정

관심 분야

  • 요즘 챙겨 보는 기술 동향 기사
  • 관심 있는 정책이나 규제
  • 카메라 렌즈 비교

고를 때 기준

  • 서로 겹치는 글이 있는 주제
  • 앞으로도 계속 찾아볼 주제
  • 한 페이지로는 안 끝나는 주제
1단계

웹 클리퍼로 자료 담기

  1. 관심 있는 글을 브라우저로 엽니다
  2. 웹 클리퍼 아이콘을 눌러 두세 개를 담습니다

    본문만 뽑혀(클리핑) raw/ 에 저장됩니다.

안 담기면 손을 들어 주시고, FAQ 4 · 웹 클리퍼 도 참고해 주세요.

2단계

정리를 실행합니다

Code 탭 아래 입력창에raw 폴더 읽어서 위키로 정리해 줘

개념을 뽑고, 겹치는 내용을 합치고, 파일로 나눠 링크를 걸고, 목차를 갱신합니다. 1~3분 걸립니다.

wiki/ 에 문서가 생기면 다음으로 넘어갑니다. 승인 창이 안 뜨거나 파일이 안 만들어지면 손을 들어 주시고, FAQ 5 · 정리 실행 도 참고해 주세요.
3단계

만들어진 문서를 확인합니다

맨 앞

프론트매터

type: 이 붙어 있어야 합니다. 이게 없으면 규격 위반입니다.

문단 끝

출처

(raw/...) 형태로 어느 자료에서 나온 이야기인지 표시돼 있습니다.

아래쪽

연결

wiki/... 로 다른 개념과 이어져 있습니다. 이게 그래프의 선입니다.

출처를 눌러 원문까지 확인합니다. AI가 지어낸 문장을 걸러 내는 가장 확실한 방법입니다.
4단계 · 오늘의 핵심 장면

자료를 하나 더 넣고 다시 돌립니다

같은 주제의 글을 하나 더 담고 정리를 다시 실행합니다. 새 문서가 여러 개 생길 것 같지만 결과는 다릅니다.

자료가 쌓일수록 문서 수가 아니라 문서의 밀도가 올라갑니다. 이것이 복리의 실체입니다.

변경 적용파일을 고치기 전에 "어디가 어떻게 바뀌는지"를 먼저 보여 주고 승인을 받는 화면. 초록색은 새로 추가되는 줄, 빨간색은 지워지는 줄입니다. diff

기록

무엇이 언제 바뀌었는지 남습니다

나중에 "지난주에 뭘 넣었더라" 싶을 때 이 파일만 보면 됩니다. AI가 알아서 적습니다.
확인

여기까지 확인합니다

  • wiki/ 폴더에 개념 문서가 세 개 이상 생겼다
  • 문서 맨 앞에 type 프론트매터가 있다
  • 문단 끝에 (raw/...) 출처가 붙어 있다
  • Obsidian 그래프에 점과 선이 보인다
  • 자료를 추가하고 다시 돌렸을 때 기존 문서에 줄이 늘어나는 것을 확인했다
비어 있는 줄이 있으면 손을 들어 주세요. 그 줄에 해당하는 FAQ도 함께 참고해 주세요 — 정리 실행 · 그래프
